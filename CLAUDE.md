# Project: Listen (macOS)

> Local-first voice dictation app for macOS. Keep this file under ~200 lines — link out to deeper docs via `@.claude/rules/...` imports.

## What this project is

Listen is a **local-first voice dictation app for macOS**. It records mic audio on a global hotkey, transcribes it **on-device** with WhisperKit, runs a deterministic text-cleanup/style/snippet pipeline, and inserts the result into whatever app is focused (via clipboard paste). Optional LLM features (grammar fix, voice-command rewrites, tone) run through an OpenAI-compatible API **or** local Ollama — but the default path is fully local with no telemetry, accounts, or bundled cloud service. This is the **public, open-source, shipped v1.0** of the macOS app (the `ListeniOS/` tree is not part of this build — see non-goals in `docs/APP_CONTEXT.md`). Audience: individual end users who want fast, private dictation; scale is single-user desktop, not a multi-tenant service.

**Business & domain context:** @docs/APP_CONTEXT.md — the always-loaded, ~2-page summary of what the app does and why (domain model, business rules, critical flows). Read it to understand the app instead of re-reading code/plans. Keep it fresh with `/context` whenever business behavior changes.

**Delivery plan:** `docs/SPRINTS.md` — the sprint-by-sprint build plan (per-sprint **Features** + **Testing** checklists, grouped by architecture/business flow). Build one sprint at a time, check off each box as it ships, and advance only when the sprint's Definition of Done holds. Read on demand, not auto-loaded.

## Stack

- **Language:** Swift 5.9 / 6 toolchain, SwiftUI + AppKit. macOS 14 (Sonoma)+, Apple Silicon.
- **Speech:** WhisperKit (on-device, CoreML) for transcription.
- **Key deps:** `HotKey` (global hotkeys), `WhisperKit` (transcription) — both via Swift Package Manager.
- **Persistence:** SwiftData (history, snippets, dictionary, style profiles, notes); UserDefaults (settings); macOS **Keychain** (LLM API keys).
- **Optional LLM:** OpenAI-compatible HTTP API **or** local Ollama — off by default.
- **Project gen / build:** XcodeGen (`project.yml` → `Listen.xcodeproj`); SPM for the `ListenCore` package.

## Critical rules (never violate)

- Never commit secrets. Never read `.env*` files unless explicitly asked.
- Never force-push to `main` / `master` / `production`.
- Never delete migrations, data, or branches without explicit confirmation.
- Always validate untrusted input at system boundaries.
- Prefer editing existing files over creating new ones.
- Match the scale of your work to the scale of the request — don't refactor when asked to fix a typo.

## Team (subagents)

Delegate via the Agent tool when the task fits a role:

- **architect** — system design, tradeoffs, tech selection
- **backend-engineer** — APIs, data models, services, perf
- **frontend-engineer** — components, state, routing, perf
- **ui-ux-expert** — layout, interaction, accessibility, design systems
- **qa-engineer** — test strategy, edge cases, regression
- **devops-engineer** — CI/CD, infra, observability, deploy
- **code-reviewer** — second-pass review focused on bugs/security/perf

**The team is on-demand, not auto-pilot** (`@.claude/rules/agent-activation.md`). Default for most work: do it inline on Opus. Delegate when it actually pays — **fan out multiple Sonnet/Haiku agents in parallel** for independent, well-specified chunks (the time+cost win), or isolate one noisy job in a cheap agent. Use specialists where they fit: architect before significant new design, ui-ux-expert before new screens, code-reviewer after non-trivial changes, qa-engineer for edge-case strategy. Agents are `model: inherit` (= Opus unless you pass a cheaper `model`); you pick the tier per task (`@.claude/rules/model-selection.md`). **Quality first:** anything a cheaper tier produces is a draft until Opus reviews it and `verify` passes; high-stakes paths (auth, payments, migrations, concurrency, money/PII) are Opus-only. Don't fan out sequential, ambiguous, or high-stakes work — keep that on Opus.

## Autonomy

This project runs in `bypassPermissions` so Claude can work for hours without babysitting. The
only guardrails are `permissions.deny` (secret reads + catastrophic commands) and the
`validate-bash.sh` PreToolUse hook (destructive-command firewall). Everything else proceeds
without prompts. Full doctrine: `@.claude/rules/autonomy.md`.

**Close the loop:** give Claude a check it can run so unattended work finishes *correct*, not just "looks done." Drop a fast `.claude/verify.sh` (typecheck/lint) and the Stop hook gates every finish on it. Always verify with evidence (test/build/lint output), never assert success.

## How to scale this boilerplate

- **Prototype / personal:** ignore most rules. Move fast. Skip QA/DevOps agents.
- **Production / startup:** enforce rules, run `/review` before merging, add basic CI.
- **Enterprise / millions of users:** use the architect agent up front, take BMAD-style specs seriously, treat security/QA/DevOps agents as mandatory gates.
